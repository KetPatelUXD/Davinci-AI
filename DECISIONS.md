# DECISIONS

Decisions taken where the build prompt left a choice (newest last).

1. **pnpm 12 / Node 24 locally.** The prompt asks for Node 22 LTS; `engines` is `>=22`. pnpm is installed through Corepack.
2. **Storybook 9.1, Vite 7, TypeScript 5.9, Vitest 3, ESLint 9.** The prompt names Storybook 9; the other majors are pinned to the versions its ecosystem supports (newer Vite/TS/Vitest majors exist).
3. **Library CSS is unlayered.** An unlayered `button { color: inherit }` reset in a host app beats any `@layer` rule, which broke label colours during development. Component rules therefore use plain class selectors (`.dv-*`, specificity 0,1,0+) so they beat element-selector resets. Tailwind's own theme/utilities stay in their layers; `base.css` is opt-in and layered.
4. **Tailwind prefix `dv:` is used for layout utilities only** (`dv:sr-only`, `dv:tabular-nums`, `dv:flex-1`, …). Surfaces (gradients, masks, spotlight) are authored as component CSS using tokens because they cannot be expressed as utilities. Tailwind theme variables are prefixed by Tailwind, so radius/shadow/font/type utilities are explicit `@utility` rules in the internal build (otherwise `--dv-radius-card` would collide with the token of the same name). The consumer preset (`@davinci-ai/react/tailwind`) is an unprefixed `@theme`.
5. **Token CSS names** use `--dv-<name>` for semantic/component tokens and `--dv-p-…` for primitives. Semantic colours are aliases of primitives; translucent values are named `alpha` primitives. `tokens.json` is written by `packages/tokens/scripts/seed.mjs` (committed; edit the tables and re-run) so the 22 Tailwind hues, alpha ramp and Figma extensions stay consistent.
6. **Graphite neutral ramp** is a custom `graphite` primitive group keyed by stop (0 white … 950 near-black) containing exactly the hexes from the prompt; light-mode text uses Tailwind zinc (900/600) which equal the prompt's values.
7. **Input boundary (WCAG 1.4.11).** Text inputs, selects, number/date fields, search fields **and** checkbox/radio boxes use a 1px `border-strong` edge. Focus is `focus` (violet) 1px inset + 3px halo — the prompt specified `border-strong` inset on focus, but that is identical to the resting border and therefore not a visible focus change (accessibility wins).
8. **Segmented control height.** The reference measures 40px for the segmented track (7px item padding + 4px track padding at 12.5px/1.45), while the prompt's size table says 38. Items are `button-height − 8px`; the track is `button-height + 2px` (md = 40) to match the reference. sm/lg follow the same +2.
9. **Pill nav items** use `line-height: 1.45` (reference) → 47.6px nav row; page title line-height 29px and card title 23px, as measured in the reference.
10. **Send button is not `disabled` when the field is empty** (the reference shows it always white). Pressing it with an empty field focuses the input instead. Streaming turns it into a Stop button.
11. **Hero chart labels and markers are HTML**, not SVG text, so they never distort under `preserveAspectRatio="none"` (circles, labels stay crisp at any size).
12. **Charts are keyboard-operable** (`←/→/Home/End/PageUp/PageDown`), expose an auto text summary, and speak only on keyboard interaction (never on hover or live ticks).
13. **Icons.** The built-in 24px stroke icon set (≈75 names, Font Awesome kebab-case names) lets the library run without Font Awesome Pro; `IconProvider`/`createIconMap` registers FA Pro definitions (a structural type, so FA stays an optional peer dependency). `assets/icons/manifest.json` lists every name the library uses.
14. **Fees in the order ticket** use `feeRate = 0.000195035` so the sample matches the reference's $412.50 on $2,115,000 notional.
15. **Colour-blind-safe and inverted-direction themes** are generated by the token build (`[data-cvd]` blue/orange, `[data-direction='inverted']` red-up); they are included in the contrast tests.
16. **Project location is inside OneDrive.** `node_modules` (~500 MB, thousands of symlinks) syncs poorly there; the pnpm store is outside (`~/.pnpm-store`). Consider excluding `node_modules`, `dist` and `storybook-static` from OneDrive sync or moving the repo.
17. **Markdown rendering is out of scope** for chat: `Prose` styles rich nodes; plug in any Markdown renderer.
18. **Token values adjusted by the contrast gate** (the automated suite found the supplied values failing 4.5:1 / 3:1 on real surfaces). Dark `border-strong` #6B6B73 → **#75757D** (3:1 against the `field` fill, not only the card). Light `text-muted` #6B6B74 → **#686871**; light `positive` text #047857 → **#065F46** (emerald-800); light `warning` text → amber-800; light `brand` text #7C3AED → **#6D28D9** (the fill stays #7C3AED); light `data-2` #E06A16 → #D2610F, `data-5` → amber-700. Light washes are 8 % (spec: 9–10 %) and dark `wash-brand` is 12 %, because status text must stay ≥ 4.5:1 on its own wash over *every* surface (subtle buttons sit on bg/hover/well too). Colour-blind-safe light negative text uses orange-800. The visual diff still passes (≤ 2.6 %).
19. **"Pure neutral ±2"** is true for the canvas ramp only; the prompt's own `raised` (#1A1A1D) is ±3 and `hover` (#222226) ±4, and its muted text greys are slightly cool. Values are kept; the test allows ±4 for surfaces.
20. **Glass is 94 % opaque** (dark; 95 % light) rather than 84 %: WebKit does not always apply `backdrop-filter`, and content scrolling underneath must never show through legibly.
21. **Motion library** (`motion`) is used for the sliding segmented thumb, count-up numerals and `MotionConfig reducedMotion="user"`; other transitions are CSS (cheaper, SSR-friendly). `tailwind-variants` was dropped: variants are `data-*` attributes + CSS, which is an "equivalent" that keeps class lists static.
22. **React Aria quirks handled:** RAC `Meter` (`role="meter progressbar"`) fails axe → own `role="meter"`; `ToggleButtonGroup` single selection is not roving → `SegmentedControl` is a `RadioGroup`; RAC toast content is `role="alert"` (assertive) → a persistent polite live region announces toasts instead.
23. **Target size (WCAG 2.5.8)** found by axe in the Storybook runner: date segments now have a 24px minimum.
24. **Docs pages** are generated: autodocs (react-docgen-typescript) plus an "Accessibility & usage" block fed by `components.json`.
25. **Browsers:** Chromium (Chrome/Edge engine) runs all visual tests; Firefox and WebKit run a cross-browser smoke spec (no errors, layout, focus ring, spotlight). Pixel diff is Chromium-only.
26. **Prettier** config is provided (`pnpm format`) but the tree was not mass-reformatted, to keep the diff reviewable.
27. **Not done / by design:** no AG Grid (grid tokens only), no chart library, no Markdown renderer, Figma kit itself is not generated here (inputs are), Code Connect URLs are placeholders, publishing is disabled, no git repository was created or pushed.
28. **Component ownership.** Components are created only in the library repo; consuming projects compose them and never restyle primitives. Base composites live in the library, project widgets in the project, promoted to the library when a second project needs them.
29. **Page templates are not part of the package.** They live in the private `packages/examples` (reference + Storybook only) and will be split into a separate templates package later. Pages import only from `@davinci-ai/react`.
30. **Storybook identity.** The animated `cover.html` is the landing story (first in the sort order); the manager is branded with the DaVinci.AI lockup and a Graphite dark theme; a "Guides → Extending the library" page documents the ownership and styling rules.
31. **Agent access plan** (not built): registry first, `davinci init`, then an optional read-only MCP server (`packages/mcp`) over `components.json`.
32. **Project memory lives in the repo** (`CLAUDE.md`/`AGENTS.md` "How we work", `PROGRESS.md`, `DECISIONS.md`), because chat sessions and Claude's local memory do not travel between machines.
