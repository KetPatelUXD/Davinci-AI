# DaVinci.AI – architecture assessment

For a senior architect deciding whether to adopt, extend or fork `@davinci-ai/react`. Facts come from the repository (state: 2026-10-05, version 0.1.0, nothing published). Judgements are marked **Assessment**.

## 1. What it is

A React design system for dense financial and AI-assistant products (the "Graphite" style). One pnpm monorepo:

| Package | Role |
|---|---|
| `packages/tokens` | Token source (`seed.mjs` → DTCG `tokens.json`) and build: CSS variables, typed TS, Tailwind theme, Figma variables/styles |
| `packages/davinci-ai` | `@davinci-ai/react`: 133 components in 10 categories, plus the generated `components.json` manifest |
| `packages/examples` | Private page templates (Markets dashboard etc.). Not published |
| `apps/storybook` | Storybook 9.1: one story file per component, docs, a11y and visual tests |
| `apps/playground` | Private dev app. Never published |

Components by category: Inputs 25, Finance 19, Display 16, Foundations 14, Layout 13, Chat 12, Navigation 11, Actions 8, Overlays 8, Data 7.

## 2. Key technology choices

- **React Aria Components** for behaviour and accessibility (keyboard, focus, ARIA). Styling is ours.
- **CSS, not CSS-in-JS.** Component styles are plain class selectors in `src/styles/*.css`, reading `var(--dv-*)` tokens. Tailwind v4 is used only for layout utilities, under the `dv:` prefix, so it cannot clash with a host app's Tailwind.
- **Unlayered CSS** (DECISIONS #3): a host app's unlayered reset (`button { color: inherit }`) would beat any `@layer` rule, so component rules are ordinary specificity-(0,1,0) classes.
- **Variants are data attributes** (`data-variant`, `data-size`, `data-selected`…) mirroring props, with React Aria's names for interaction state. Class lists stay static.
- **Motion** (`motion`) only where JS animation is needed (sliding thumb, count-up). Everything else is CSS transitions. `MotionConfig reducedMotion="user"` is set globally.
- **Charts are custom SVG/HTML**, no chart dependency. Keyboard-operable with an auto text summary.
- **Peers:** React 18.2 or 19, `react-dom`; Font Awesome Pro and Inter are optional peers. Runtime deps are small: `react-aria(-components)`, `@internationalized/date`, `motion`, `clsx`.
- **ESM only**, `sideEffects: ["**/*.css"]`.

## 3. Theming model

Three token tiers:
1. **Primitives** (`--dv-p-*`, 415 of them): raw values. Components never reference them.
2. **Semantic roles** (83 per mode): `--dv-brand`, `--dv-surface`, `--dv-text-secondary`… Aliases of primitives, redefined per mode.
3. **Component tokens**: sizes, radii, heights (`--dv-button-height-md`, `--dv-radius-card`).

`ThemeProvider` writes `data-theme`, `data-style`, `data-density`, `data-card-border`, `data-direction` and `data-cvd` onto a wrapper (and `<html>` with `attachToRoot`). The stylesheet keys off those attributes, so switching mode, density or direction needs no re-render and no JS styling. Providers nest, so a region can be themed independently.

Dark is the default experience. Light, colour-blind-safe (blue/orange) and inverted-direction (red-up) palettes are generated by the token build, not hand-maintained.

**Rebranding:** override only the brand roles (`--dv-brand`, `--dv-brand-fill`, `--dv-wash-brand`, `--dv-focus`, `--dv-focus-halo`). `npx davinci theme --primary <hex>` generates the override CSS and tunes the colour until contrast rules pass (white on fill ≥ 4.5:1, brand text ≥ 4.5:1 on every surface, focus ≥ 3:1). Status colours (`positive`/`negative`) are independent of brand.

**Theme file:** a project can supply one DTCG-style JSON file (brand, radius, density, fonts, per-mode colour overrides). A single pure compiler (`bin/lib/theme-core.mjs`, also bundled into the library) turns it into scoped CSS custom properties and enforces the contrast rules; it is used by the CLI (`davinci theme --file`) for a static stylesheet and by `ThemeProvider themeConfig` at runtime. `davinci theme --from-figma` imports a Figma variables export. The JSON Schema is generated from the resolved tokens. Guide: `docs/theming-guide.md`.

**Limit:** only one style (`graphite`) exists. The `styleName` hook is there but there is no second implementation.

## 4. Single sources of truth and generation

Code is the source of truth; everything else is generated and gated.

- `seed.mjs` → `tokens.json` → CSS / TS / Tailwind / Figma variables.
- `components.json` (props, enums, defaults, states, keyboard/ARIA notes, anatomy with token names, CSS block and parts, Figma properties) is generated from component sources and `scripts/components.config.mjs`. It feeds docs, AI assistants and Figma.
- **Figma** is derived from rendered components: Storybook `Internal/Extract*` stories → `scripts/figma-extract.mjs` (own cascade and `var()` resolver, token matching) → builder. Hover, motion and live data are code-only.
- **Stories** are generated by `scripts/gen-stories.mjs` from `components.json` plus a hand-written `scripts/stories.spec.mjs` (315 stories incl. interaction stories). Never edit generated stories by hand.

## 5. Quality gates

`pnpm test:all` = typecheck, lint, unit tests, build, Storybook build, Storybook tests in dark and light, and visual tests.

- **Lint** also runs token lint (no hex/primitives in component CSS), `check-naming` and `check-anatomy --strict` (CSS parts must equal manifest anatomy).
- **Unit:** 423 Vitest tests, including 180 contrast tests (every text/icon token × every surface incl. lit card corner and spotlight, across dark, light, CVD and inverted) and axe on every component.
- **Storybook runner:** 447 tests, render plus axe on every story. Run in dark and light.
- **Visual:** Chromium pixel diffs (the Markets dashboard story differs from the reference HTML by 1.3 % dark / 2.6 % light). Firefox and WebKit run a smoke spec only.
- Contrast failures changed some supplied token values (DECISIONS #18). Accessibility wins over the reference.

## 6. Conventions that matter when extending

- One name everywhere: React export = manifest key = Storybook title = CSS block (`dv-kebab-name`) = Figma component set. Parts are flat `dv-{block}__{part}`. See `docs/naming-convention.md`. Enforced by `pnpm check:naming`.
- Props vocabulary is fixed: `variant`, `intent` (never `tone`), `size`, `orientation`, `isX` booleans.
- A new component needs: React Aria-based component with JSDoc (`@when` / `@whenNot`), token-only CSS, story, axe test, manifest entry, export, changeset.
- Ownership (DECISIONS #28): components are only created in the library repo. Consumers compose; project-specific widgets live in the project and are promoted to the library when a second project needs them.

## 7. Assessment

**Strengths**
- Accessibility is enforced by tests rather than convention (contrast across all token/surface pairs, axe everywhere, keyboard behaviour for charts).
- Tokens are the single source for CSS, TS, Tailwind and Figma, so drift is mechanically unlikely.
- Styling is plain CSS over CSS variables: SSR-safe, no runtime styling cost, simple to override.
- The machine-readable manifest makes the library unusually well suited to AI-assisted development.
- Small dependency surface.

**Risks and gaps**
- **React-only.** Not directly usable from Angular or Vue. Options are wrapping (React root or custom elements) or porting against the same CSS, tokens and manifest. The CSS depends on the React-produced markup, so a port must reproduce it exactly.
- **Not distributed.** Version 0.1.0, nothing published. Registry (GitHub Packages) is planned. Consumers currently install a `pnpm pack` tarball. No semver history or upgrade path yet.
- **Scale gaps:** no virtualised `Table`, no AG Grid theme (grid tokens only), no full chart library (axes, comparison, candlesticks), no Markdown renderer.
- **Single visual style.**
- **Test coverage:** pixel diffs are Chromium only. React 18 is supported in `peerDependencies` but not exercised in tests.
- **Figma sync is a pipeline, not a link.** Correct if the component was correct when extracted. A broken component produces a wrong Figma component silently. Not every state is expressible in Figma.
- **Naming debt:** some parts are named only in the extractor config because the DOM lacks a `dv-` class (PageHeader eyebrow/title, UserChip, Banner, QuoteCard). Tracked in `PROGRESS.md`.
- **Repo lives in OneDrive**, which syncs `node_modules` poorly. Exclude `node_modules`, `dist`, `storybook-static`.

## 8. Adoption options

| Option | Effort | Notes |
|---|---|---|
| Use as-is in a React app | Low | Install, import `styles.css`, wrap in `ThemeProvider`, run `davinci theme` for brand |
| Wrap in a non-React host | Medium | Fast parity; carries a React runtime |
| Port to another framework | High (133 components) | Reuse tokens, CSS and manifest; rebuild behaviour (e.g. Angular CDK) |
| Fork and extend | Medium | Follow the new-component checklist and naming gates |

**Before relying on it in production:** publish to a registry with versioning, run the React 18 matrix in CI, and decide on virtualisation for large tables.
